What this project is

We built a live IoT Virtual Commissioning environment that feeds real Festo CP Lab production data — via OPC-UA, Node-RED and MQTT — directly into Siemens NX, TIA Portal and Simatic Robotic Suite. The result: a virtual twin that reflects what is actually happening on the physical line, not just a static simulation.

01

The Problem

Traditional virtual commissioning is disconnected from reality. Engineers travel to site, lose production time finding code faults, and work with static simulations that don't reflect what the real plant is doing. Licenses and vendor lock-in add to the cost.

02

Our Solution

A two-PC IoT pipeline: real CP Lab data is acquired via OPC-UA, transformed in Node-RED, published to HiveMQ via MQTT, and consumed by a full Siemens NX + TIA Portal virtual commissioning environment, live, vendor-agnostic, and scalable.

A key enabler in this workflow is the Simatic Robot Programming Suite, a highly important, non-vendor-specific tool we are using. It gives engineers direct access to a comprehensive library of major robot manufacturers, significantly simplifying the integration and programming of robots introduced into the virtual commissioning environment.

03

Why It Matters

This project bridges the gap between IoT and virtual commissioning: a gap that costs industry millions. It reduces travel, cuts fault-finding time, improves adaptability, and points toward a future where commissioning engineers work remotely with confidence.

System Architecture
at a Glance

Four layers connect the physical Festo CP Lab to a fully operational virtual commissioning environment across two computers, secured with MQTT over TLS following the Purdue cybersecurity model.

Project Plan

Structured Stages

From feasibility research to validated virtual commissioning demonstration

Stage 01 · Research Phase

Feasibility Study & Architecture Design

Investigated whether an IoT-connected virtual commissioning environment was technically feasible. Studied communication protocols, reviewed Purdue cybersecurity model, and designed the two-PC architecture with OPC-UA → Node-RED → MQTT → HiveMQ → Virtual Env pipeline.

CompleteOPC-UAPurdue ModelMQTT
Stage 02 · Communication Deployment

Protocol Integration & Data Pipeline

Deployed OPC-UA server on PC 1 to acquire CP Lab data. Configured Node-RED to transform JSON payloads into OPC-UA-compatible format. Established MQTT over TLS connection to HiveMQ cloud broker. Validated end-to-end data flow using UA Expert as OPC-UA subscriber.

CompleteNode-REDHiveMQUA Expert
Stage 03 · Virtual Environment Setup

Robot Programming & NX Digital Twin

Programmed the robot in Simatic Robotic Suite — imported reference frames for the output station, validated pickup points. Replicated robot positioning in Siemens NX. Configured all relevant I/O signals in the NX file for synchronisation with the PLC.

CompleteSimatic Robotic SuiteSiemens NXSignal Mapping
Stage 04 · PLC Integration & Validation

TIA Portal Programming & Communication Validation

Programmed TIA Portal V20 for system control. Validated NX ↔ Simatic Robotic Suite communication with signals being sent correctly. Demonstrated automatic cell functioning to show overall feasibility — all components operational, showcasing the project's full potential despite licensing constraints.
