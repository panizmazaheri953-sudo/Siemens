The problem
with traditional
commissioning

  • 01
    Costly site visits: Engineers must be physically present to test PLC logic against live machinery, causing expensive travel and production downtime.
  • 02
    Late-stage errors: Bugs in control software are discovered only when hardware is installed — when changes are most expensive to implement.
  • 03
    No parallel validation: The physical machine must exist before any logic can be verified, creating a serial bottleneck in the project timeline.
  • 04
    Safety risks: Initial commissioning on live systems poses real hazards to personnel and equipment when untested code is executed.

Our virtual
commissioning
approach

01

Digital Twin Creation

A high-fidelity virtual replica of the physical system is built using Siemens NX and Tecnomatix, mirroring every sensor, actuator, and conveyor in software.

02

Virtual PLC Loop

The real TIA Portal PLC program runs against the virtual model via OPC-UA. Control logic is tested, debugged, and optimised entirely in simulation.

03

IoT Data Stream

Sensor data from the virtual environment is streamed to Siemens MindSphere, enabling real-time monitoring, anomaly detection, and performance dashboards.

04

Validated Handover

Only after all KPIs are met in simulation does the system go live — with a proven, validated configuration that transfers directly to the physical installation.

Project Roadmap

Development phases — from concept to validated virtual commissioning

Phase 01 · Weeks 1–2

System Mapping & Digital Twin Setup

Document the physical CP Lab line, identify all I/O signals, and create the base kinematic model in Tecnomatix NX MCD. Establish OPC-UA server configuration.

NX MCD Tecnomatix In Progress
Phase 02 · Weeks 3–4

Virtual PLC Integration

Connect TIA Portal program to PLCSIM Advanced. Map all signals between virtual controller and digital twin. Run first closed-loop simulation cycle.

TIA Portal V18 PLCSIM Advanced OPC-UA
Phase 03 · Weeks 5–6

IoT Data Pipeline

Configure MQTT broker to stream real-time sensor data from the virtual environment to Siemens MindSphere. Build initial KPI monitoring dashboard.

MindSphere MQTT Node-RED
Phase 04 · Weeks 7–8

Validation & Benchmarking

Run structured commissioning tests against defined acceptance criteria. Compare virtual vs physical performance metrics. Document deviation analysis.

Competition Submission & Documentation

Finalise all documentation, technical blog, demo video, and submit to Siemens Xcelerator. Present results with live simulation demonstration.
